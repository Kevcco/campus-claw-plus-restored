# PNG/JPEG 私有 OCR 与准确私有 HTTP 合同

2026-11-16，小张，DI-SC-16/17/19/25。本批新增图片输入、沿用同一 Tesseract/Leptonica 研究镜像及模型，没有新增解码依赖。生产仍 Target6、28 current、15 空 active；图片原件公开上传、OCR 版本 API、校对页和默认服务装配尚未交付。

## 实际行为

PNG 先校验签名、IHDR、合法位深/颜色组合、CRC、有界分块、完整 IEND 和20MP，拒绝 APNG/未知关键块；只保留编码像素、调色板和透明度。JPEG 校验8位单帧 SOF0/1/2、1/3/4分量、尺寸、标记/扫描边界和准确 EOI，拒绝拼接/MPO；去掉 EXIF/XMP/ICC/注释，保留 APP14 色彩解释。这里是准入策略；本轮实际语料主要为已有开发集，并非所有编码组合逐一质量验收。

坐标使用编码像素，不以 EXIF 元数据旋转图片。原件不被改写；仅在临时目录给现有 Leptonica 解码器提供移除无关元数据后的输入。单张图片由独立子进程在15秒内完成准入/解码/OCR/序列化；512MiB/1CPU、只读、32进程、64MiB临时盘和10MiB输入限制保持。服务总185秒/客户端190秒与 PDF 规则保持。成功结果要求 TSV 尺寸与准入尺寸一致、码点词段逐字匹配；不返回半结果。

原生子进程 SIGKILL、超时与基础设施错误使用不同闭合标签；未知异常不会被算成识别准确率成功。输出文件先查字节上限再读入，响应过大统一422/resource_limit，与 Go 状态码映射和新合同一致。模拟原生失败的单测不冒称真实 OOM 实验。

## 真实开发集与回归

- 原有4张独立开发正例（中文/英文，PNG/JPEG）：实际接口正文25/1618码点错误，micro CER1.545%。每个成功响应另跑2020-12 Schema及 Go 严格出处/原图尺寸检查。
- 10张低质开发负例：10/10为 low_quality 或明确识别失败。计数依据诊断质量/失败原因，不因所有成功结果本来都 needs_review 就判通过；阈值仍是开发诊断，未冻结生产质量门槛。
- 两个真实元数据变体（PNG eXIf、有效 JPEG EXIF orientation6）：与原编码像素的 OCRResult 字节相同。另真实私有请求拒绝超20MP、损坏PNG、损坏JPEG，分别得到准确资源/损坏原因。
- 旧4页 PDF→私有 RPC→租约 worker→MySQL→校对revision2→学生逐字出处检索与实际取消释放再次通过，437词框、CER35/1618=2.16%；13组 MySQL 事务仍全通过。
- 识别容器实际仅有7个白名单代码文件，无 gold、盲测或 fixtures。Go调用器只取得14个开发输入及尺寸清单，宿主独立评分；50页盲测和100框IoU没有运行。

本轮 raw-results.json、images.json、image-tests.txt、pipeline-tests.txt、server-logs.txt 是最终实际运行，包含2个元数据不变性和3个真实拒绝检查。images.json 的 elapsed_ms 是该测试用例的时间；dev-01/02还包含元数据变体请求，不能当单次 OCR 性能数值。所有专属容器/网络/临时凭据已清理。

## 准确合同和检查

[private-openapi.json](../../../../docs/contracts/ocr-draft/private-openapi.json) 与 private-rpc.json 具体定义固定 origin、bearer、三个媒体、成功/错误状态码、no-store 和服务端请求标识。复用唯一 OCRResult Schema；2020-12单源/解引用对相同正反例一致，禁止200携失败或错误携半正文，实际 HTTP 单测核对头。公开 openapi.json 只保留校对草案，删除其中过时的私有 path，避免维护两套私有状态集合；公开新版本读取/列表搜索兼容合同仍待完善，未注册新公共接口。

默认check新增图片准入/原生失败分类4组，Python总10组，私有合同2组和Go媒体/拒绝单测。关闭PNG/JPEG像素守卫的隔离同源副本红1，恢复绿0，活动源码不被破坏。原有90秒 PDF/取消实测预算不改；新增14图片/元数据/拒绝测试单独使用240秒测试进程预算，不改变15秒单页或任何原门禁。

追加复验曾在本机默认 Docker 地址池耗尽时失败，network-pool-failure.json保留。当时独立检查正在使用最后一个自动子网；现在复用已有 verificationSubnets 分配显式未占用/24，仍为专属 internal 网络，实际检查 Internal=true，不删除或修改其他项目网络。修复后最终真实运行通过。

完整check、audit及最终提交检查见后续补记；早期 audit TLS失败原件保留，未降低严格TLS或安全门槛。完整native许可/漏洞闭包、混合页、真实OOM、正式盲测/IoU、生产迁移激活和公开页面仍待，不把本批记为B整体完成。
