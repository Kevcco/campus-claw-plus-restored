## 已实现的行为

GET OCR状态、原始识别源、显式修订，POST校对、开始识别、显式重试，以及GET OCR关键词检索。每次调用现有身份服务Me，以可信当前班级授权；学生不可写或读原始稿，只能看已发布资料及历史review修订。校对201 Location指向不可变修订，开始/重试202指向状态。开始按文档自然幂等，重复不重跑失败作业；重试只对三种允许原因、attempts<3生效。与原TXT/Document写入共用12次/用户分钟配额。

原件version1、原202和原识别快照保持。教师输入按原Unicode/空白存储，包含分解字符的文本不被归一化；旧修订按页和码点回读，不套用旧词框。检索q对齐现有2000码点，片段4096/重叠1999，输出当前发布修订的逐字出处、标题和显式URL；跨班和旧索引均不命中。旧200码点组件上限不再限制新HTTP合同。

请求严格拒绝未知/重复/错误大小写字段和额外query；业务5秒包括认证、body及SQL。校对解码正文2MiB，HTTP上限12MiB+64KiB容纳合法Unicode转义；真实最大转义请求成功，超过解码上限失败。准确OpenAPI/单源Schema/锁定摘要在docs/contracts/ocr-public，旧draft只作共享Schema编译入口，避免两套公开path。该组件冻结不代表整个B1.2安全/质量/生产装配已验收。

## 读取截止时间缺陷

新增慢body测试最初使用io.Pipe客户端阻塞，本轮单个Go容器已明确识别后主动停止（退出137），没有将其计成功；后改用固定7秒截止的原始TLS连接、保持连接且不加Connection: close。OCR/Document/TXT三个路由均真实超7秒未返回，见keepalive-red.txt。

修复为统一5秒业务context和socket读取截止，保持截止直到net/http完成未读body处理；下一请求由服务器重新设置截止。原Document/OCR不再在handler defer中提前清零；TXT也将认证与body纳入同一5秒，并把网络超时映射504。三路绿0，服务端截止5秒，原始TLS完整读完/收尾约5.51秒；没有声称网络关闭开销也在严格5秒内，更没有修改任何旧门禁。健康3秒/SQL/TLS/原响应格式不变。

另在隔离同源副本故意给缺失bearer填入测试token，匿名请求拒绝测试红1；恢复绿0。没有改活动代码或制造新真实身份会话。
